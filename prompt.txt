I'd like the api be built in python with flask and it extensions :
The api should be:
    rate limited
    restricted to domain

There should be domain entities that perform business logics:
 domain/
     entities/

Services and repositories communicate through entities only ( so there should be mapper that map entities and orm ). entities should have no dependancies with other layers.

There should be repositories with one ABC for repositories that defines repositories contracts, one ABC for unit of work that defines unit of works contracts and a package for sql repositories that make requests to database. Repositories never own session, they get sessions through services.
domain
    repositories/
        sql/
            sql_uow.py
            .....
        utilis/ or utils.py # mapper should come from here
        base_uow.py
        base_repository.py

The repository contract should be:
    add
    get(EntityId)
    list(EntityFilter)
    __apply_filter(Query)
    update(Entity)
    delete(Entity)

list should always return a pagination object and repositories always return Entity.

No business logic in repositories, they only execute and query.

All repositories should be aggregated in one sql unit of work.

The services layer grant permissions and perform actions on domains or entities and should always return a ServiceResult object with consistent data and always raise on error ( errors are registered and centralized ).

Services have one ABC class that define contracts. Services method names should be meaningful and short. 
All domain services must be aggregated into one class and added to the app as extension.

Services never receive row json.

domain
    services/
        ....
        domain_service.py 

The route is responsible for accepting requests, validating them and passing data between services and api clients, nothing beyond that. All routes responses must be consistent accross all domains ( same response schéma everywhere ) using envelopes

routes use schemas ( pydantic ) to Validate, serialize and deserialize data.

routes must be versioned and documented 
domain/
    routes/
        v1/
            schemas/

All routes are imported and registered into the app.

The app should register Middlewares, ErrorHandlers enforce content types etc.


There should be configuration for dev, testing and production ( production config or settings should be set in env ) and created using pydantic-settings.

config/


src/
    config/
    app/
    domains/
        domain/
            entities/
            repositories/
            services/
            routes/

Communication between domain should be done through events and are emited by entities.
